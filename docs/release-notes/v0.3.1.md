# v0.3.1 — fix moduleDeps crash on Scala.js / custom binders

A correctness fix for the `moduleDeps` walk shipped in `0.3.0`. Builds that
were failing with "Cannot find … in reconciled versions" after upgrading can
drop `--no-module-deps` again.

```yaml
mill-build:
  mvnDeps:
    - "io.eleven19.mill-github-dependency-graph::mill-github-dependency-graph_mill$MILL_BIN_PLATFORM:0.3.1"
```

## Fixed: `moduleDeps` walk crashed when the depender binds differently (#32)

`0.3.0` started reporting dependencies reached through internal `moduleDeps`.
It bound those coordinates with the *depender's* `bindDependency`, not the
dependency module's.

That is fine when every module shares the same binder. It is not fine when a
library rewrites coordinates and a depender does not — the shape
`finos/morphir-scala` hits on Scala.js: library modules platform versionless
YAML `::` coords to `_sjs1_3`, while `ScalaJSTests` children keep Mill's
default binder and produce the JVM key (`_3`). `DependencyTree` then looked
up a module the resolution never held and aborted the whole run:

```
Cannot find io.getkyo:kyo-jsonrpc_3 in reconciled versions
```

`--no-module-deps` restored working behaviour by skipping the walk, at the
cost of the accuracy fix that was the point of `0.3.0`.

Each dependency module's coordinates are now bound with **that** module's
`bindDependency`. The walked roots match what the resolution reconciled, so
the depender's manifest reports them instead of crashing.

## Upgrading

Bump the version. No flag or code changes. If you added `--no-module-deps`
only to work around this crash, you can remove it.
